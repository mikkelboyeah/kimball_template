# 02 — TO-BE Target Architecture

This document describes **everything you must build** to implement the full analytics stack for a
new domain. Work through the layers in order — each layer depends on the one above it.

The insurance domain is the reference implementation. File paths and names below use
`<domain>` and `<star_name>` as placeholders. Replace them with values derived from the domain
markdown (see [03-reading-the-target-markdown.md](03-reading-the-target-markdown.md)).

---

## Layer 0 — Preparation

Before writing any code, identify all star schemas from the domain markdown:
- Each **fact table** in the markdown becomes one star schema.
- Name each star schema in `snake_case` (e.g., `claim_accumulated_snapshot`,
  `fact_policy_transactions`, `premium_periodic_snapshot`).
- The **star schema name** becomes the subfolder name used consistently across all layers.

---

## Layer 1 — Data Generators

**Location:** `src/data_generators/<star_name>/`

Create two scripts per star schema:

### `generate_facts.py`

Generates the fact table as a Parquet file. Pattern:

```python
import pandas as pd
import numpy as np
import random
import os

def generate_mock_data(num_rows=5000):
    np.random.seed(42)
    random.seed(42)
    data = []
    for i in range(num_rows):
        # Build one dict per row. Include:
        # - All foreign key columns (e.g., customer_id, date_id, product_id)
        #   Use integer ranges: random.randint(1, N) for dimension keys
        # - Date columns as 'YYYY-MM-DD' strings
        #   Use datetime objects with a DEFAULT_DATE = '9999-12-31' sentinel for unknown dates
        # - Degenerate dimension strings (e.g., order_number, invoice_number)
        # - Numeric measure columns (float, rounded to 2dp)
        # - Lag columns for accumulating snapshots (integer days between milestone dates)
        data.append({ ... })
    df = pd.DataFrame(data)
    script_dir = os.path.dirname(os.path.abspath(__file__))
    out_dir = os.path.abspath(os.path.join(script_dir, '..', '..', '..', 'data', 'raw', '<star_name>'))
    os.makedirs(out_dir, exist_ok=True)
    df.to_parquet(os.path.join(out_dir, '<fact_table_name>.parquet'), index=False)

if __name__ == '__main__':
    generate_mock_data()
```

Key rules:
- Use `np.random.seed(42)` and `random.seed(42)` for reproducibility.
- Foreign keys must reference IDs generated by `generate_dims.py` — use the same integer ranges.
- For accumulating snapshots: model milestone dates chronologically with `datetime + timedelta`.
  Use `datetime(9999, 12, 31)` for "not yet reached" milestones (e.g., close date for open claims).
- For periodic snapshots: generate one row per entity per month-end date.
- All column names: `snake_case`, `_id` suffix for surrogate keys.
- Output: one `.parquet` file in `data/raw/<star_name>/`.

### `generate_dims.py`

Generates all dimension tables as Parquet files. Use this complete pattern:

```python
import pandas as pd
import numpy as np
import random
import string
import os

# ── Path constants ──────────────────────────────────────────────────────────────
SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
RAW_DIR = os.path.abspath(os.path.join(SCRIPT_DIR, '..', '..', '..', 'data', 'raw', '<star_name>'))
os.makedirs(RAW_DIR, exist_ok=True)

# ── Helpers ─────────────────────────────────────────────────────────────────────
def random_alphanumeric(length=8):
    return ''.join(random.choices(string.ascii_uppercase + string.digits, k=length))

def get_unique_keys(df_fact, column_name):
    """Extract sorted unique values of a FK column from the fact table."""
    return sorted(df_fact[column_name].dropna().unique())

def save(df, name):
    df.to_parquet(os.path.join(RAW_DIR, f'{name}.parquet'), index=False)

# ── dim_date ────────────────────────────────────────────────────────────────────
def generate_dim_date(df_fact):
    """Build a complete date spine from all date FK columns in the fact table.

    IMPORTANT: date_id is stored as a string 'YYYY-MM-DD' (NOT an integer).
    Fact table date FK columns are also stored as strings, so joins work directly.
    The sentinel '9999-12-31' is included as a placeholder row for unknown dates.
    """
    date_cols = [c for c in df_fact.columns if c.endswith('_date_id')]
    all_dates = pd.concat([df_fact[c] for c in date_cols]).dropna().unique()

    dates_df = pd.DataFrame({'full_date': all_dates})
    dates_df = dates_df[dates_df['full_date'] != '9999-12-31'].copy()

    min_date = pd.to_datetime(dates_df['full_date']).min()
    max_date = pd.to_datetime('today').normalize()

    if pd.isna(min_date):
        min_date = max_date - pd.DateOffset(years=5)
    else:
        min_date = min(min_date, max_date - pd.DateOffset(years=5))

    date_range = pd.date_range(start=min_date, end=max_date, freq='D')
    df = pd.DataFrame({'full_date': date_range})
    df['date_id']     = df['full_date'].dt.strftime('%Y-%m-%d')
    df['full_date']   = df['full_date'].dt.strftime('%Y-%m-%d')
    df['year']        = pd.to_datetime(df['full_date']).dt.year
    df['month']       = pd.to_datetime(df['full_date']).dt.month
    df['month_name']  = pd.to_datetime(df['full_date']).dt.strftime('%B')
    df['quarter']     = 'Q' + pd.to_datetime(df['full_date']).dt.quarter.astype(str)
    df['day_of_week'] = pd.to_datetime(df['full_date']).dt.strftime('%A')
    df['is_weekend']  = np.where(pd.to_datetime(df['full_date']).dt.dayofweek >= 5, 'Yes', 'No')
    df['is_holiday']  = np.random.choice(['Yes', 'No'], size=len(df), p=[0.03, 0.97])

    # Sentinel row for unknown / not-yet-reached dates
    sentinel = {
        'date_id': '9999-12-31', 'full_date': '9999-12-31', 'year': 9999,
        'month': 12, 'month_name': 'Unknown', 'quarter': 'Unknown',
        'day_of_week': 'Unknown', 'is_weekend': 'Unknown', 'is_holiday': 'Unknown'
    }
    df = pd.concat([df, pd.DataFrame([sentinel])], ignore_index=True)
    df = df[['date_id', 'full_date', 'year', 'month', 'month_name', 'quarter',
             'day_of_week', 'is_weekend', 'is_holiday']]
    save(df, 'dim_date')

# ── Domain-specific dimensions ──────────────────────────────────────────────────
# Add one function per dimension table. Read unique keys from the fact table and
# generate descriptive attributes for each. Low-cardinality dims (status, type)
# can use a small hard-coded set; high-cardinality dims derive from fact FK ranges.

def generate_dim_<entity>(fact_keys):
    num_rows = len(fact_keys)
    df = pd.DataFrame({'<entity>_id': fact_keys})
    df['<entity>_name']   = [f'<Entity> {k}' for k in fact_keys]
    df['<attribute>']     = [random.choice(['A', 'B', 'C']) for _ in range(num_rows)]
    # ... add more columns as defined in the ER diagram
    save(df, 'dim_<entity>')

# ── Entry point ─────────────────────────────────────────────────────────────────
def main():
    np.random.seed(42)
    random.seed(42)

    fact_parquet = os.path.join(RAW_DIR, '<fact_table_name>.parquet')
    df_fact = pd.read_parquet(fact_parquet)

    generate_dim_date(df_fact)
    generate_dim_<entity>(get_unique_keys(df_fact, '<entity>_id'))
    # ... call each generate_dim_X function

    print(f"Successfully generated all dimension Parquet files in {RAW_DIR}")

if __name__ == '__main__':
    main()
```

Key rules:
- Run `generate_facts.py` **before** `generate_dims.py` — dims depend on the fact file existing.
- `date_id` in `dim_date` is a **string** `'YYYY-MM-DD'`, matching the fact table's date FK columns. Do NOT use integer date keys.
- Include `'9999-12-31'` as a sentinel row in `dim_date` to match fact rows with unknown dates.
- All date FK columns in the fact table end in `_date_id` — the `generate_dim_date` function auto-detects them.
- Output: one `.parquet` file per dimension in `data/raw/<star_name>/`.
- Low-cardinality dimensions (status, type, profile) can have hard-coded small sets of rows.

## Layer 2 — Source Definitions

**File:** `transform/models/src_raw.yml`

Add one entry under `sources.raw.tables` for **every Parquet file** your generators produce:

```yaml
- name: <fact_table_name>
  description: "<brief description>"
  external:
    location: "../data/raw/<star_name>/<fact_table_name>.parquet"
- name: dim_<dimension_name>
  external:
    location: "../data/raw/<star_name>/dim_<dimension_name>.parquet"
# ... repeat for all tables in this star schema
```

Notes:
- The `name` must exactly match the Parquet filename stem (without `.parquet`).
- All tables in all star schemas live under the same `sources.raw` source — use unique names
  across schemas (prefix with schema context if needed, e.g., `dim_date` is shared).
- The `external.location` is a relative path from the `transform/` folder to `data/raw/`.

## Layer 3 — dbt Staging Models

**Location:** `transform/models/staging/<star_name>/`

Create one staging model per raw table. Staging models are pass-through (no transformation):

```sql
-- stg_<prefix>__<table_name>.sql
select * from {{ source('raw', '<table_name>') }}
```

Naming convention: `stg_<short_prefix>__<table_name>.sql`
- `<short_prefix>`: 3-5 character abbreviation of the star schema (e.g., `claim_acc`, `pol_txn`)
- Example: `stg_claim_acc__dim_claim.sql`, `stg_pol_txn__fact_policy_transactions.sql`

No `.yml` documentation files are required in staging — the mart layer handles descriptions.

---

## Layer 4 — dbt Mart Models

**Location:** `transform/models/mart/<star_name>/`

Create one mart model per table (fact + all dimensions). Mart models select from staging:

```sql
-- fct_<fact_name>.sql
select * from {{ ref('stg_<prefix>__<fact_table>') }}

-- dim_<dimension_name>.sql
select * from {{ ref('stg_<prefix>__dim_<dimension_name>') }}
```

Optionally add `.yml` files for column-level documentation if required.

The mart layer materialises as tables (`+materialized: table`) in the `mart` schema.

---

## Layer 5 — dbt Reporting Models

**Location:** `transform/models/reporting/<star_name>/`

The reporting layer is what gets exported to Parquet and consumed by Power BI. It contains:

### Fact reporting view

```sql
-- fct_<fact_name>_reporting.sql
select * from {{ ref('fct_<fact_name>') }}
```

### Dimension reporting views (one per dimension)

```sql
-- dim_<name>_<star_name>.sql
select * from {{ ref('dim_<name>') }}
```

The `_<star_name>` suffix disambiguates dimension views that may share the same logical name
across star schemas (since dbt model names must be unique project-wide).

### `schema.yml` — table aliases and descriptions

```yaml
version: 2
models:
  - name: fct_<fact_name>_reporting
    config:
      alias: fct_<fact_name>       # This becomes the Parquet filename and PBI table name
    description: "Fact table for <description>"
  - name: dim_<name>_<star_name>
    config:
      alias: dim_<name>            # Clean alias without the star schema suffix
    description: "Dimension table for <description>"
  # ... repeat for all dimensions
```

The `alias` value is critical: it determines the **Parquet filename** in `data/exports/` and
therefore the **table name** in the Power BI semantic model.

## Layer 6 — dbt Project Configuration

**File:** `transform/dbt_project.yml`

Add one entry per new star schema under `models.generic_project.reporting`:

```yaml
models:
  generic_project:
    reporting:
      <star_name>:
        +schema: reporting_<star_name>
```

This is what causes dbt to write this star schema's reporting views to a separate DuckDB schema
(`reporting_<star_name>`), which `export_reporting.py` then targets.

---

## Layer 7 — Taskfile Updates

**File:** `Taskfile.yml`

Add `uv run python` lines to the `generate-data` task body, one per generator script:

```yaml
generate-data:
  desc: Generate mock <domain> data as Parquet files
  cmds:
    - uv run python src/data_generators/<star_name_1>/generate_facts.py
    - uv run python src/data_generators/<star_name_1>/generate_dims.py
    - uv run python src/data_generators/<star_name_2>/generate_facts.py
    - uv run python src/data_generators/<star_name_2>/generate_dims.py
    # ... repeat for each star schema
```

## End-to-End Data Flow Summary

```
[generate-data]
  src/data_generators/<star>/generate_facts.py  →  data/raw/<star>/<fact>.parquet
  src/data_generators/<star>/generate_dims.py   →  data/raw/<star>/dim_*.parquet

[ingest]
  dlt pipeline  →  DuckDB raw schema  (raw.<table_name>)

[transform-prod]
  dbt staging   →  DuckDB staging schema  (view, pass-through)
  dbt mart      →  DuckDB mart schema  (table, star schema)
  dbt reporting →  DuckDB reporting_<star> schema  (view, denorm for export)

[export-reporting]
  DuckDB reporting_<star> →  data/exports/<star>/<alias>.parquet

[generate-powerbi]
  data/exports/<star>/*.parquet  →  powerbi/<star>/<star>.SemanticModel/  (TMDL)
                                 →  powerbi/<star>/<star>.Report/
```

`transform/models/mart/claim_accumulated_snapshot/` as the primary reference examples.
